## 1. 무엇을 만들려는 프로젝트인가

한 줄을 넣으면 원하는 그림체로 4컷 만화가 나오게 하는 것이다.
그런데 "이 그림체로 그려줘"를 기계가 어떻게 알아듣냐가 문제다.
프롬프트에 "수묵화풍으로"라고만 쓰면 생성 모델이 학습 때 본 평균적인 수묵화가 나오고, 컷마다 달라진다.

그래서 **그 그림체의 실물을 찾아다 생성에 물린다.** 텍스트를 검색하는 대신 그림을 검색하는 것이고,
구조로 보면 RAG 그대로다. 찾아오는 대상만 문서에서 그림으로 바뀐다.

| RAG 자리 | 이 프로젝트에서 |
|---|---|
| 문서 코퍼스 | 그림체 코퍼스 |
| 텍스트 임베딩 | CLIP 이미지·텍스트 임베딩 |
| 검색된 청크 | 검색된 레퍼런스 그림 |
| 답변 생성 | 그림 생성 |

RAGAS 네 지표도 그대로 옮겨진다. 이 중 둘은 이미 숫자를 냈고 둘은 아직 안 돌렸다(아래 5절).

모델은 셋이고 하는 일이 다르다.

| 모델 | 하는 일 | 어디서 |
|---|---|---|
| gpt-4o | 4컷 대본 (글자 -> 글자) | OpenAI API |
| gpt-image-1 | 그림 (글자 -> 픽셀) | OpenAI API |
| CLIP | 검색과 채점 | 내 컴퓨터 (로컬) |

셋 다 학습을 안 시킨다. 그래서 3일에 가능하다고 봤다.

## 2. 검색기가 될지부터 확인했다 (실측)

말로만 하면 안 될 것 같아서 먼저 돌려봤다.

**가설**: 아무것도 안 가르친 모델이 뱉는 숫자만으로 그림체가 갈리나?
**재는 법**: 그림 한 장을 던져 가장 가까운 5장을 보고, 그중 같은 그림체가 몇 장인지 센다.

처음엔 **찍는 것보다 5.3배**가 나왔다. 그런데 이웃을 열어보니 **같은 화가 그림들**이었다.
그림체 하나에 화가가 1~10명뿐이라, 그림체를 찾은 게 아니라 화가의 붓버릇을 찾고 점수를 받아간 것이다.

- 화가당 최대 8장으로 제한
- 질의한 그림의 화가를 이웃 후보에서 제외

다시 재니 **2.94배**. 숫자는 내려갔지만 이게 맞는 숫자다.

## 3. 더 근본적인 의심 — 그림체를 재는 건가 내용을 재는 건가

수묵화 데이터에 **같은 원본을 다른 기법으로 그린 통제쌍**이 있어서 그걸로 확인했다.

| 그림 한 장을 던졌을 때 가장 가까운 5장이 | 무작위 대비 |
|---|---|
| 같은 **내용** (같은 그림을 다른 기법으로) | **102배** |
| 같은 **그림체** (다른 그림인데 같은 기법) | **1.5배** |

즉 검색 임베딩은 **그림체보다 "무엇이 그려졌나"를 먼저 본다.**
그림체는 픽셀에 분명히 있고 사람은 알아보는데 임베딩은 아직 잘 못 본다.

그래서 채점기에 **자기 자신 + 같은 원본 제외**를 넣었다. 안 빼면 그림체가 아니라 내용을 재게 된다.

## 4. 코퍼스와 채점기 (팀이 쓸 판)

### 코퍼스 — 난이도 스펙트럼을 만들었다

| 도메인 | 클래스 | 장수 | 난이도 | 누수 차단 |
|---|---|---|---|---|
| ink | 흑백 회화 기법 9종 | 1,259 | 어렵다 (색 단서가 없다) | 같은 **원본** 제외 |
| paint | WikiArt 사조 6종 | 565 | 중간 | 같은 **작가** 제외 |
| vector | 공개 라이선스 일러스트 5종 | 698 | 쉽다 | - |

합 **2,522장 / 20클래스 / 57MB** (코랩에서 도는 크기).

일부러 쉬운 것도 넣었다. 실제 서비스는 전 코퍼스에서 찾아야 하니까. 대신 **클래스별·도메인별로 따로 보고**한다.

### 채점기 — 규격 하나만 지키면 점수가 나온다

```python
def encode(images):        # PIL.Image 리스트
    return vectors         # numpy (N, D) float32
```

```bash
python score.py encoders/내방법.py --name "이름-방법"
```

- **부트스트랩 95% 구간**을 같이 찍는다. 같은 코드를 두 번 돌려도 숫자는 흔들리기 때문이다
- `compare.py` 로 두 방법을 **짝지어 비교**한다. 같은 그림들로 채점받았다는 사실을 쓰면 훨씬 예민하게 갈린다
- 질의별 점수를 남겨서 나중에 되짚을 수 있다

## 5. 기준선 두 개 — 그리고 답을 모르는 지점

| 방법 | 전체 p@5 | 무작위 대비 | 95% 구간 |
|---|---|---|---|
| CLIP 그대로 (출발점) | 0.3986 | 7.72배 | 0.3855 ~ 0.4128 |
| Gram VGG19 (첫 시도) | **0.4914** | **9.52배** | 0.4781 ~ 0.5055 |

짝지어 비교 **+0.0928, 구간 [0.0793, 0.1062]** -> Gram 승.

Gram 은 VGG 중간층에서 채널끼리 내적해 **위치를 지운다.** 위치가 사라지면 "어디에 무엇이"가 날아가고
"어떤 결이 얼마나 같이 나타나나"만 남는다. 대가는 차원이 512에서 174,560으로 뛴 것이다.

### 그런데 도메인을 쪼개면 승자가 뒤집힌다

| 도메인 | CLIP | Gram | 승자 |
|---|---|---|---|
| ink | 0.2262 (2.05배) | **0.3595 (3.26배)** | Gram |
| **paint** | **0.5324 (2.94배)** | 0.3706 (2.05배) | **CLIP** |
| vector | 0.6510 (3.27배) | **0.8481 (4.27배)** | Gram |

클래스로 내려가면 더 심하다. `paint_Cubism` 은 CLIP 0.70 vs Gram 0.28.

**내 짐작**: 회화 사조는 붓결보다 색과 구도로 갈리는데 Gram 은 그걸 버린다.
반대로 흑백 회화는 색이 없어 붓결이 전부라 Gram 이 이긴다. **확인은 안 했다.**

짝지어 비교에서 Gram 이 이겼지만 **606개 질의에선 CLIP 이 나았다**(1183승/606패/733무).
그래서 "최고의 표현 하나"를 찾는 문제가 아닐 수도 있다. **여기가 팀이 풀 자리다.**

## 6. 생성까지 붙여봤다 — 되는 것과 안 되는 것

발표 직전까지 그림을 한 장도 안 만들어봤다는 걸 깨닫고 붙여봤다.
같은 장면·같은 모델(gpt-image-1)로, **레퍼런스를 넣었는지만** 다르게.

**된다**: 그림이 나온다. 한 장에 **$0.046, 18~21초**. 4컷 한 편이면 $0.18.
말로만 "수묵화 화풍"이라고 하면 컬러 반짝이가 남는데, 레퍼런스를 넣으면 색이 빠지고 먹 톤으로 끌려온다.

**안 된다**: 그게 **얼마나** 끌려왔는지 못 잰다.
코퍼스 유사도가 0.547에서 0.565로 **0.018** 움직였다. 진짜 수묵화는 0.635~0.683인데.
솔직히 사람이 봐도 애매하다. **n=2 라 "레퍼런스가 이겼다"고 말할 수도 없다.**

## 7. RAGAS 네 지표 상태

| 지표 | 이미지판에서 | 계산 방법 | 지금 |
|---|---|---|---|
| context_precision | 검색된 5장이 정말 그 그림체인가 | 그림체 라벨과 대조 | ✅ 위 리더보드 |
| context_recall | 그 그림체를 놓치지 않았나 | 같은 라벨로 재현율 | 🔶 코드는 같은 자리, **미실행** |
| faithfulness | 생성 그림이 그 그림체에 충실한가 | 생성물 vs 코퍼스 임베딩 거리 | ✅ 0.547 -> 0.565 |
| answer_relevancy | 생성 그림이 컷 내용에 맞는가 | 장면 문장 vs 생성 그림 CLIP 유사도 | 🔶 **미실행** |

정답이 있는 지표는 **라벨 대조**로, 정답이 없는 지표는 **임베딩 거리**로 계산한다.
RAGAS 라이브러리를 그대로 돌리는 게 아니라 정의만 이미지로 옮겨 직접 계산한다.
(RAG 실습에서 한국어 answer_relevancy 가 음수로 나오는 걸 겪어서 라이브러리를 그대로 믿지 않기로 했다)

## 8. 준비하면서 틀린 것 세 개

셋 다 **에러가 안 났고 숫자도 그럴듯했다.** 그래서 기록해둔다.

1. **작가를 맞히고 있었다** — 5.3배 -> 2.94배 (2절)
2. **내용을 재고 있었다** — 내용 102배 vs 그림체 1.5배 (3절)
3. **수집 스크립트가 250장 받고 전부 틀린 그림이었다** — 에러 0, 개수 정상, 로그 정상.
   12장을 콘택트시트로 만들어 눈으로 보고 잡았다. 받아온 건 전부 사이트 UI 버튼이었다.
   원인이 두 겹(호스트 필터 오류 + 가장 긴 URL 선택)이라 "항상 성공하는데 항상 틀린" 코드가 돼 있었다.

-> 그래서 규칙을 하나 만들었다. **수집·전처리는 끝나고 표본 10장 남짓을 눈으로 본다.**
