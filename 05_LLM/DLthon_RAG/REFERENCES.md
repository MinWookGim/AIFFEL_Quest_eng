# 참고자료

이 프로젝트에서 실제로 참고한 것들을 한곳에 모았다. 흩어져 있던 걸 옮겨온 것이라
각 항목이 **어디에 어떻게 쓰였는지**를 같이 적었다.

**읽은 정도를 구분해서 적는다.** 제목만 보고 인용하면 나중에 질문받을 때 무너지므로,
직접 읽고 적용한 것과 개념만 가져온 것을 나눠뒀다.

---

## 1. 지표 — 읽고 적용한 것

검색 성능을 무엇으로 잴지 정할 때 조사한 것들이다. 전문은 `04_임베딩_실험/지표_조사.md`.

| 자료 | 무엇을 얻었나 | 어디에 쓰였나 |
|---|---|---|
| **ALADIN: All Layer Adaptive Instance Normalization for Fine-grained Style Similarity**<br>https://arxiv.org/pdf/2103.09776 | 스타일 검색을 **IR Top-1/5/10** 으로 평가한다는 것 | 우리도 같은 계열(p@5)로 가기로 한 근거 |
| **Measuring Style Similarity in Diffusion Models**<br>https://arxiv.org/html/2404.01292v1 | 스타일 유사도를 **mAP · Recall@k** 로 평가 | Macro mAP@5 를 보조 지표로 채택 |
| **Mean Average Precision (MAP) in ranking** (Evidently AI)<br>https://www.evidentlyai.com/ranking-metrics/mean-average-precision-map | mAP 개념과 계산 | p@5 와 AP@5 의 차이를 이해하고 둘 다 보기로 |
| **What is Mean Average Precision (mAP)?** (Milvus)<br>https://milvus.io/ai-quick-reference/what-is-mean-average-precision-map | mAP@k 계산식 | 채점기 구현 검산 |

**k=5 로 고정한 이유**는 논문이 아니라 우리 제품에서 나왔다 — 생성 모델에 참조 이미지를
5장 물릴 계획이라 검색기가 뽑은 5장이 곧 서비스 품질이다.

## 2. 방법의 뿌리 — 개념만 가져온 것

논문을 처음부터 끝까지 읽고 구현한 게 아니라, **널리 알려진 방법을 가져다 쓴 것**이다.
정직하게 이 칸에 둔다.

| 방법 | 어디서 온 개념 | 우리 구현 |
|---|---|---|
| **Gram 행렬로 그림체를 뽑기** | Gatys 등의 신경망 스타일 전이에서 쓰는, 특징맵 채널 간 상관(Gram)이 내용이 아니라 화풍을 담는다는 아이디어 | `kit/encoders/gram_vgg19.py` — VGG19(ImageNet 사전학습)의 `relu1_1 · relu2_1 · relu3_1 · relu4_1` 네 층에서 Gram 을 뽑아 이어붙인다 (174,560 차원) |
| **CLIP 임베딩으로 이미지 검색** | 이미지·텍스트를 같은 공간에 놓는 대조학습 | `kit/encoders/clip_base.py` — `openai/clip-vit-base-patch32` 를 그대로 사용 |

**Midjourney 스타일 레퍼런스 문서**
https://docs.midjourney.com/hc/en-us/articles/32180011136653-Style-Reference
-> *"원하는 그림체를 얻기 어려우면 참조 이미지에 맞는 묘사 단어를 프롬프트에 넣으라"* 는 안내가 있다.
즉 **그림체 맞추기가 사용자 손일로 넘어와 있다**는 근거로 썼다 (발표 4장).
페이지 직접 접근이 403 이라 도메인 한정 검색으로 문구를 확인했다.

## 3. 쓴 모델 · 라이브러리

전부 **사전학습된 것을 그대로 조합**했다. 학습은 한 번도 하지 않았다.

| 자리 | 무엇 | 비고 |
|---|---|---|
| 대본 작성 | `gpt-4o-mini` (temperature 0.7) | 이야기 한 줄을 4컷 장면으로 쪼갠다 |
| 이미지 생성 | `gpt-image-1` (1024x1024, quality medium) | 편당 4컷 · 약 $0.20 · 92초 |

| 그림체 검색 · 채점 (Gram) | `torchvision` VGG19 `IMAGENET1K_V1` (174,560차원) | 붓결 · 질감 쪽을 본다 |
| 파이프라인 뼈대 | **LangGraph** | 앞 컷을 뒤 컷에 넘겨야 해서 상태를 명시적으로 들고 가는 구조가 필요했다 |
| 협업 구조 실험 | **AutoGen** | 작가 · 비평가 두 에이전트가 대본을 주고받는 구조를 따로 짜봤다. 파이프라인 전체를 옮기지는 않아 정량 비교는 없다 |

## 5. 업계 동향 확인 (2026-08-11) — 2차 자료

발표 주장("생성이 요청을 안 따라온다" / "검수가 비어 있다")이 우리 실측 바깥에서도 성립하는지
확인한 것이다. **논문이 아니라 기사·커뮤니티 글이라 경향만 참고했고 숫자는 인용하지 않는다.**

- 레퍼런스 조건화가 **짧은 구간에서만 듣고 길어지면 흐트러진다**는 실무 보고
- **모델 업데이트가 공들여 만든 스타일을 깨뜨린다** — OpenAI 개발자 포럼, Adobe Firefly 포럼 스레드
- **캐릭터 일관성**이 이미지 생성 분야의 최장기 미해결 문제로 꼽힌다는 정리
- 연구 쪽에는 **스타일 특화 CLIP-I · DINO 기반 스타일 일관성 · Style Consistency Score** 같은
  자동 지표가 이미 있다. 다만 **하나의 지표가 스타일 충실도와 다양성을 동시에 못 잡아
  사람 평가를 병행**한다는 것도 같이 보고된다

-> 그래서 **"우리만 그림체를 숫자로 잰다"고는 말하지 않는다.** 지표는 연구에 있고,
우리가 비어 있다고 보는 건 **그게 쓰는 사람 화면에 점수로 오지 않는다**는 쪽이다.
그리고 "점수가 사람 판단과 맞는지"를 못 잰 것은 우리만의 구멍이 아니라 이 분야의 열린 문제다.
