### 오후 — 첫 회의: 역할 대신 갈래

각자 배경지식과 경험이 달라서 진도 속도와 관점이 다르다는 게 확인됐다. 역할을 못박는 대신
오늘은 갈래별로 빌드업부터 하기로 했다.

- 임베딩 빌드업: 진현, 수경 (수경이 팀 디스코드도 개설)
- 랭그래프·오토젠 빌드업: 나, 희연
- 경수는 프로젝트 파악을 더 하기로
- 내일(7/31) 다시 모여 진행사항과 방향을 회의

### 저녁 — 랭그래프·오토젠 빌드업 노트북 제작

희연님과 같이 볼 코랩 노트북(`빌드업_랭그래프_오토젠.ipynb`)을 만들었다. 설계 원칙:

- **키가 없어도 끝까지 돈다.** LLM·이미지 생성·채점을 흉내(mock) 함수로 채워 뼈대만 먼저 검증.
  키를 넣으면 대본 작성만 진짜 LLM으로 바뀐다
- 파이프라인 4노드(대본 작성 -> 그림체 주입 -> 이미지 생성 -> 채점) + "점수 미달이면 프롬프트
  보강해서 재생성" 루프. 그림체 주입 노드가 임베딩 갈래와 만나는 접점이다
- 이미지 생성은 장당 비용이 들어서 자리표시 이미지로 대체 (진짜 생성은 팀이 비용 규칙을 정한 뒤에)
- 오토젠은 작가·비평가 두 에이전트가 대화로 대본을 다듬는 구조. "합격" 발화로 종료

### 헛발질 기록 (같은 곳에서 안 넘어지기)

1. **OpenAI 키가 소리 없이 죽어 있었다.** 코랩에서 401이 나서 추적해보니 키 자체가 무효화돼 있었다
   (전날까지 잘 돌던 키였다). 유출 여부부터 검사했고(배포 파일 전체에 키 문자열 없음 확인) 새 키로
   교체했다. 교훈: 키가 "없을 때"만 대비했는데 "잘못됐을 때" 노트북이 통째로 죽는 구조였다.
   -> LLM 호출이 실패해도 흉내 모드로 물러나게 고쳤다
2. **자리표시 이미지 속 한글이 전부 네모로 깨졌다.** PIL 기본 폰트에 한글 글자가 없어서다.
   개수·크기만 확인하고 렌더 결과를 눈으로 안 본 게 원인. 나눔고딕을 설치·로드하게 고쳤다.
   교훈: 그림이 나오는 코드는 돌아갔는지가 아니라 나온 그림을 봐야 검증이다
3. 검증 순서도 배웠다: 목 모드(키 없음) -> 죽은 키 재현 -> 실키 콜드 스타트, 세 경로를 다
   돌려본 뒤에야 팀원에게 넘겼다
