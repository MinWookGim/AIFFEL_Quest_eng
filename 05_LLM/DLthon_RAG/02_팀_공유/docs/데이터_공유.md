# 데이터 공유 — 무엇을 나눠줄 수 있고 무엇은 안 되나

**결론부터**: 코퍼스를 통째로 못 나눠준다. 출처마다 조건이 다르다.
그래서 **나눠줄 수 있는 것만 모은 공유팩**을 따로 만들었고, 나머지는 **각자 받아 재현**하는 방식으로 간다.

### ★ AI-Hub 데이터 팀 내부 공유에 대한 판단 (2026-07-30, 팀장 김민욱)

**조항 원문(5항)**: "제공 받은 AI데이터 등을 수행기관 등과 한국지능정보사회진흥원의 승인을 받지 않은
다른 법인, 단체 또는 개인에게 열람하게 하거나 제공, 양도, 대여, 판매하여서는 안됩니다."

**판단**: 아이펠 교육 과정의 같은 팀 5~6명이 비영리 학습 목적으로만 쓰는 범위라면
공유해도 무리가 없다고 보고 **팀 내부 공유로 진행한다.**

**그래도 지키는 선 두 개**
1. **공개 저장소(깃허브)·공개 링크에는 원본 이미지를 올리지 않는다.** 팀 내부 전달만
2. **출처를 반드시 밝힌다** — 한국지능정보사회진흥원 사업결과물(1항)

**참고로 조항을 좁게 읽으면 이렇다** (판단 근거를 남겨두기 위해 적어둔다)
- 국적 관련은 **2·3항**(국외 소재 개인·국외 반출)이고, **5항은 국내에서도 적용**된다
- "같은 팀"이라는 예외는 조항에 없다. 조항이 요구하는 건 수행기관·NIA 의 승인이다
- 각 팀원이 **본인 명의로 신청해 받으면 조항 안에서 해결된다** (아래 3절 방법)

### ★ 추가 판단 (2026-08-10, 팀장 김민욱) — 발표·문서에 싣는 **예시 이미지**

**왜 다시 적나**: 위 7/30 판단의 "지키는 선 1번"을 *"원본 이미지는 공개 저장소에 일절 안 올린다"* 로
넓게 읽으면, 이미 어긋난 상태다. 7/29 발표 PDF(`01_기획/DLthon_발표_그림체RAG.pdf`)가 공식 깃허브에
올라가 있고 그 안에 **AI-Hub 168 수묵화 원본 12장**이 들어 있다 (2쪽 4장 · 7쪽 6장 · 14쪽 2장).
2026-08-09 전수 감사에서 확인했다.

**판단**: **두 가지를 갈라서 본다.**

| | 무엇 | 판단 |
|---|---|---|
| **데이터셋 배포** | zip·폴더·대량 이미지 — 받는 사람이 **데이터로 재사용할 수 있는 형태** | ❌ 계속 금지. 5항의 "제공"에 해당한다고 본다 |
| **예시 인용** | 발표 자료·문서에 **근거로 몇 장 싣는 것** (해상도 축소·설명 딸림) | ✅ 허용. 학술·교육 발표의 인용이지 데이터 제공이 아니라고 본다 |

가르는 기준은 **"받는 사람이 이걸로 데이터셋을 복원할 수 있는가"** 다. 12장으로는 못 한다.

**이 판단에 딸린 의무 — 지키지 않으면 판단이 성립하지 않는다**

1. **출처를 자료에 직접 밝힌다** (이용정책 **1항**: 2차 저작물에도 사업결과임을 밝혀야 한다).
   ★ 2026-08-10 확인: **7/29 발표 PDF 전문에 AI-Hub 언급이 0건이다.** 7쪽 "(저작권 확인 완료)" 뿐이다.
   저장소 수준에서는 이 문서·README·제안서에 표기가 있지만, **이미지를 담은 자료 자체에는 없다.**
   -> **8/11 자료에는 반드시 한 줄 넣는다**:
      *"ink(수묵화) 이미지 출처: AI-Hub 168 한국화 데이터 — 한국지능정보사회진흥원 사업결과물"*
2. **필요한 만큼만.** 근거로 필요한 최소 장수. 그림체 견본을 무더기로 깔지 않는다
3. **いらすとや도 같은 선**을 적용한다 (재배포 제한. 예시 인용은 되되 배포는 안 된다)
4. **원본 해상도로 싣지 않는다.** 슬라이드 크기로 줄여서 넣는다

**택하지 않은 선택지** (나중에 왜 이렇게 했는지 알 수 있게 적어둔다)
- 발표 PDF 의 수묵화 12장을 공개 라이선스 그림으로 갈아 재푸시 -> git 히스토리엔 남아 실익이 적다
- PDF 를 저장소에서 내림 -> 7/29 기록이 사라진다. 작업 이력이 평가 대상이라 손해가 크다

## 2. 그래서 팩이 둘이다

| 팩 | 내용 | 크기 | 어디까지 |
|---|---|---|---|
| `daypack_v2` | ink 9 + paint 6 + vector 5 = **2,522장 20클래스** | 57MB | 🔶 **팀 내부 공유** (공개 링크 금지) |
| `daypack_share_v1` | paint 6 + vector 4 = **1,123장 10클래스** | 27MB | ✅ **제약 없음.** 공개해도 됨 |

두 팩을 다 두는 이유: 팀원은 `v2` 로 바로 시작하고, **발표·깃허브·외부 공유가 필요한 자리에는
`share_v1`** 을 쓴다. 출처 조건을 신경 쓸 필요가 없는 판이 하나 있어야 편하다.

★**두 팩의 점수는 서로 비교하지 않는다** (팀 규칙 2 — 코퍼스 구성이 다르다).
리더보드에 코퍼스 버전 칸이 있으니 섞이지 않는다.

## 3. (선택) 각자 본인 명의로 받아 재현하는 방법

팀 내부 공유로 가더라도, **본인 명의로 받아두는 게 가장 깔끔하다**(특히 이 데이터를 DLthon 이후
개인 프로젝트나 포트폴리오로 이어갈 사람). **seed 를 고정해뒀으니 각자 돌리면 똑같은 팩이 나온다.**

```
1) AI-Hub 가입 -> "168. 한국 전통 수묵화 화풍별 제작 데이터" 이용 신청 (본인 명의)
2) 01-1.정식개방데이터 를 받아서 아래 경로에 둔다
     _scratch/ETC/DLthon/data/Ai-Hub 데이터/168.한국 전통 수묵화 화풍별 제작 데이터/
3) python build/make_daypack.py        # 1,259장 / 9클래스 / 29MB 생성 (seed 20260729)
4) python build/make_daypack_v2.py     # 공유팩과 합쳐 20클래스 v2 재현 (seed 20260730)
```

**이라스토야도 같은 방식**이다: `python build/fetch_irasutoya.py`
(요청 간 1.2초 · 250장 상한이 걸려 있다. 남의 서버니 그대로 쓰기)

## 4. 공유 수단

| 무엇 | 어디로 | 왜 |
|---|---|---|
| `daypack_v2.zip` (57MB) | **팀 채널 / 팀 전용 드라이브** | 팀 내부 전달만. **공개 링크로 걸지 않는다** |
| `daypack_share_v1.zip` (27MB) | 어디든 | 출처 조건만 지키면 제약 없음 |
| `kit/` (채점기·비교기·기준선) | **공식 깃허브** | 코드라 자유 |
| `build/*.py` (재현 스크립트) | **공식 깃허브** | 각자 재현하는 데 필요 |
| 문서 (브리핑·규칙·이 문서) | **공식 깃허브** | |
| **원본 이미지 — 데이터로 쓸 수 있는 형태** (zip·폴더·대량) | ❌ **공개 저장소·공개 링크에는 안 올림** | AI-Hub 5항 · 이라스토야 재배포 제한 |
| **원본 이미지 — 발표·문서의 예시 인용** (몇 장, 설명 딸림) | 🔶 **된다. 단 출처 표기 필수** | 위 "추가 판단 (2026-08-10)" 참고 |
| 임베딩 `.npy` | 올려도 되지만 **안 올린다** | 403MB 짜리가 있어 무겁다. 재계산이 몇십 초 |
