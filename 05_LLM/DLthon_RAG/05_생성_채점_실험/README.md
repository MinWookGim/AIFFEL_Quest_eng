# 생성 쪽 채점 실험 (2026-08-03, 개인 연구)

7/29 발표 때 남은 숙제가 계속 걸려서 혼자 파봤다.
**v1 동결본은 하나도 안 건드렸다.** 여기 있는 건 전부 새 파일이고, 8/10에 팀이 보고 쓸지 말지 정하면 된다.

결론부터 적으면 이렇다.

1. 우리는 **검색에는 정답이 있는데 생성에는 채점자가 없었다.** 그래서 생성 실험이 n=2에서 멈췄다
2. 채점자를 만들고 나서 보니 더 앞에 문제가 있었다 — **4컷이 서로를 모른다**
3. 잰 것 다섯 중 셋은 기각됐다. 기각된 데서 발표에 쓸 숫자가 나왔다

## 1. 왜 했나 — 0.018이 남긴 것

발표 직전에 생성을 처음 붙여봤을 때 점수가 0.018만 움직였다. 그때 "n=2라 이겼다고 말하면 안 된다"로
정직하게 처리하고 넘어갔는데, 다시 보니 **못 잰 게 아니라 잴 도구가 없었던 것**이었다.

우리 파이프라인을 검색과 생성으로 갈라 보면 이렇게 비어 있었다.

| | 검색 | 생성 |
|---|---|---|
| 정답 | `meta.csv`의 `style` 컬럼 (m1~m9, 1,259장 전부) | "m3로 그려줘"라는 요청문 |
| 정답과 대조하는 수단 | `p@5` | **없음** |
| 표본 | 1,259장 | n=2 |

정답은 사실 양쪽 다 있었다. **없었던 건 생성물에 라벨을 붙이는 방법**이다. 코퍼스 그림에는
`meta.csv`가 라벨을 달아주는데, 방금 생성된 그림에는 아무도 안 달아준다.

그래서 **역방향 채점**을 쓰기로 했다. 생성물을 코퍼스에 질의로 던져 가장 가까운 5장을 찾고,
그 5장의 라벨로 생성물을 판정한다. 검색기를 라벨 붙이는 도구로 재활용하는 것이라
새 모델도 새 지표도 필요 없다.

## 2. 오늘의 제일 큰 발견 — 4컷이 서로를 모른다

채점 방법을 만들다가 생성 코드를 들여다봤는데, `build/gen_style_test.py`(내 로컬 실험 코드)가
컷마다 독립으로 API를 부르고 있었다. 매 컷이 **같은 레퍼런스 3장만** 보고 그려진다.
앞 컷이 다음 컷에 안 들어간다.

```
지금        컷1 <- [레퍼런스 3장]
            컷2 <- [레퍼런스 3장]      서로 모름
            컷3 <- [레퍼런스 3장]
            컷4 <- [레퍼런스 3장]

바꾸면      컷1 <- [레퍼런스 3장]
            컷2 <- [레퍼런스 3장 + 컷1]
            컷3 <- [레퍼런스 3장 + 컷1]
            컷4 <- [레퍼런스 3장 + 컷1]
```

컷 간 일관성이 안 나오는 게 당연했다. **채점으로 잡을 문제가 아니라 생성 구조 문제**였다.
하루 종일 "어떻게 잴까"를 팠는데 그 앞에 "왜 안 되는가"가 있었다.

비용은 이미지 입력이 3장에서 4장으로 느는 것뿐이라 컷당 0.002달러 정도다. 실측 장당 0.046달러와
비교하면 사실상 공짜다. 그리고 여기가 랭그래프의 state가 실제로 쓰이는 자리이기도 하다 —
앞 노드 결과를 state에 담아 다음 노드로 넘기면 된다.

이걸 확인할 실험 코드를 `ab_prev_cut.py`로 짜뒀다. **아직 안 돌렸다.**

## 3. 잰 것들

수묵화 코퍼스로 쟀다. 생성 API는 안 썼고 이미 있는 임베딩만 썼다. 무작위는 9클래스라 0.111.

**아래 숫자는 전부 `생성_채점_연구_0803.ipynb`를 실제로 실행해서 나온 출력이다.**
손으로 옮겨 적은 게 아니라 그 노트북이 단일 출처다. 표본을 다시 뽑는 방식이라
돌릴 때마다 소수점 셋째 자리가 조금씩 흔들리는데, 이 문서의 숫자는 노트북에 박힌 실행 결과와 맞춰뒀다.

### (1) 컷 간 코사인 유사도로 그림체를 가릴 수 있나 -- 못 가린다

```
같은 그림체 4장   중앙 0.669   5~95% [0.584 ~ 0.773]
다른 그림체 4장   중앙 0.656   5~95% [0.578 ~ 0.735]
```

차이가 0.013이고 분포가 거의 완전히 겹친다. 수묵화끼리는 코사인이 죄다 0.65 근처다.
"수묵화다"라는 공통 신호가 자릿수를 다 먹어서 그림체 차이는 소수점 둘째 자리에서 논다.

**그래서 판정에서 빼고 복붙 탐지용 상한으로만 남겼다.** 4컷이 완전히 같은 그림이면 1.000이 나오니
`0.95 초과`면 "일관성이 높은 게 아니라 복붙"으로 막는다.

### (2) 채점은 CLIP이 아니라 Gram으로 해야 한다

같은 임베딩이라도 절대값 대신 **순위**로 보면 갈린다. 이웃 5장의 최다 라벨로 판정해봤다.

| | 무작위 | CLIP | Gram VGG19 |
|---|---|---|---|
| 컷 단위 라벨 정확도 | 0.111 | 0.296 | **0.440** |
| 편(4컷) style precision 중앙 | 0.111 | 0.250 | **0.500** |
| 4컷 전부 같은 라벨 | 거의 0 | 0.021 | 0.065 |
| 다른 그림체 4장이 전부 같은 라벨 | -- | 0.004 | **0.000** (2000회 중 0회) |

CLIP은 천장이 0.25라 무작위 0.111과의 폭이 0.14뿐이다. 잴 공간이 없다. Gram은 폭이 두 배다.

### (3) 진짜 그림도 만점을 못 받는다 -- 천장이 0.500이다

**진짜 m3 그림 4장을 넣어도 style precision 중앙값이 0.500이다.** 즉 4컷 중 2컷만 m3로 판정된다.
생성물이 이걸 넘을 수 없다. 우리 시험의 천장이 0.5인 것이다.

그래서 점수를 절대값으로 읽으면 안 되고 이렇게 정규화해야 한다.

```
정규화 = (측정값 - 무작위) / (천장 - 무작위)
       = (측정값 - 0.111) / (0.500 - 0.111)

1.0 이면 진품만큼 한 것, 0 이면 무작위와 같은 것
```

라벨 효용도 클래스마다 다르다. 1,259장 코퍼스에서 m3는 무작위의 3.34배인데 m9는 1.48배다.
**실험용 그림체는 천장 높은 것(m3, m2, m1)으로 골라야 한다.** m9로 재면 잴 수 있는 폭이 0.05뿐이라
점수가 낮게 나와도 생성이 못한 건지 라벨이 무의미한 건지 못 가른다.

### (4) 채점기를 여러 개 모아 투표시키면 나아지나 -- 안 나아진다

앙상블이 먹히려면 서로 다른 데서 틀려야 하는데, 그 조건은 만족했다.

```
둘 다 맞힘    0.173
CLIP 만 맞힘  0.124
Gram 만 맞힘  0.267
둘 다 틀림    0.437

한쪽이라도 맞힌 비율 0.563  vs  단독 최고 0.440   ->  이론상 여지 +0.124
```

그런데 실제로 투표시키면 1:1에서 0.384로 **떨어진다.** Gram에 4배 가중치를 줘야 0.455로 겨우
넘어서고, 그 +0.0152마저 짝지어 비교하면 95% 구간이 [-0.0254 ~ +0.0558]이라 **아직 모른다**가 답이다.

원인은 실력 차다. CLIP 0.296과 Gram 0.440은 차이가 커서 **약한 표가 강한 표를 희석시킨다.**
오류가 안 겹치는 건 필요조건이지 충분조건이 아니었다.

**남은 수확이 더 값지다: `둘 다 틀림 0.437`.** 임베딩 두 개를 합쳐도 44%는 아무도 못 맞힌다.
채점기를 더 얹어서 풀 문제가 아니라 **문제 자체가 어렵다는 증거**다.

### (5) 채점기를 판정에 쓰지 말고 선택에 쓰면 확 오른다

같은 Gram 채점기인데 질문을 바꿔봤다. "이게 m3인가?"(판정) 대신
"후보 N장 중 뭐가 제일 m3다운가?"(선택)로.

| N | 진짜를 고를 확률 | 무작위 | 배수 |
|---|---|---|---|
| 2 | 0.795 | 0.500 | 1.59 |
| 3 | **0.704** | 0.333 | 2.11 |
| 5 | 0.581 | 0.200 | 2.90 |

**판정 0.440이 선택 0.704가 됐다.** 모델을 안 바꾸고 얻은 차이다.
절대 판정은 임계값이 필요한데 그 선이 클래스마다 다르고, 상대 비교는 선이 필요 없어서다.

## 4. 팀에 전하고 싶은 것 두 가지

### (가) 빌드업 노트북의 재생성 루프, 지금 채점기로는 쓰면 안 된다

`03_빌드업/빌드업_랭그래프_오토젠.ipynb`에 "점수 미달이면 프롬프트 보강해서 재생성" 루프를
넣어뒀는데, 위 실측을 보고 나니 **지금 채점기로 그 루프를 돌리면 손해**다.

채점기 정확도가 0.440이라는 건 뒤집으면 **진짜 m3 그림의 56%를 "m3가 아니다"라고 잘못 짚는다**는
뜻이다. 잘 그린 걸 버리고 다시 그리게 되니, 루프를 돌수록 나빠질 수 있다.

같은 채점기라도 쓰임새에 따라 손해가 다르다.

| 쓰임새 | 채점기가 틀렸을 때 | 최악의 경우 |
|---|---|---|
| 버리기 (실패 판정하면 재생성) | 잘 그린 걸 버린다 | 돌수록 나빠짐 |
| 고르기 (N장 뽑아 최고를 선택) | 아무거나 고른 셈 | 무작위 뽑기와 같음 |

**채점기가 약할 때는 버리는 데 쓰면 안 되고 고르는 데 써야 한다.** 그래서 루프 대신
컷당 3장 뽑아 고르는 방식(best-of-3)을 제안한다. 생성비가 3배(편당 0.18달러에서 0.55달러)로
늘지만, 지금까지 잰 것 중 노이즈 바닥을 확실히 넘은 유일한 개선이다.

되돌아가는 루프는 **이유를 말하는 채점기**가 생긴 다음이다. 숫자만 뱉는 채점기는
"틀렸다"는 말하지만 "왜"는 못 말해서, 되돌아가도 뭘 고칠지 모른다.

### (나) 점수를 볼 때 천장을 같이 보자

우리 리더보드 숫자를 절대값으로 읽으면 다 낮아 보인다. 그런데 **진짜 그림도 0.500이 천장**이다.
평가규칙(`02_팀_공유/docs/팀_평가규칙.md`)에 "무작위 대비 배수로 읽는다"를 이미 적어뒀는데,
생성 쪽에는 여기에 **천장**을 하나 더 붙이는 게 맞다.

발표에 쓸 문장으로 옮기면 이렇게 된다.

> 우리가 못한 게 아니라 이 문제의 천장이 여기입니다. 그리고 우리는 그 천장을 쟀습니다.

### `gate.py`가 하는 일

임계값을 미리 정해두고 편마다 통과/탈락을 매긴다. 탈락하면 **어디를 고쳐야 하는지까지** 알려준다.

```
통과 G-m3-01  정규화 +1.00
탈락 G-m3-02  X 컷이 빠졌다 - 3/4컷. 고칠 곳: 출력 스키마 검증
탈락 G-m5-01  X 그림체가 안 잡혔다 - 0.25 < 0.50. 고칠 곳: 레퍼런스 선택
탈락 G-m2-01  X 4컷이 사실상 같은 그림이다 - 0.985 > 0.95. 복붙이다
통과 G-m4-01  정규화 +1.64
```

통과선은 style precision 0.50(4컷 중 2컷)으로 잡았다. 근거는 이렇다.

| 통과선 | 진짜 그림이 통과하는 비율 | 무작위가 통과하는 비율 |
|---|---|---|
| 0.25 (4컷 중 1컷) | 84.4% | 37.6% |
| **0.50 (4컷 중 2컷)** | 53.8% | **6.4%** |

0.25로 잡으면 무작위도 37.6%가 통과해서 게이트 노릇을 못 한다.
(무작위 통과 확률은 이항분포로 계산했다)

### 채점기와 다른 점 두 가지

기존 채점기(`02_팀_공유/kit/score.py`)는 "몇 점인가"를 내고, 게이트는 "내보낼 수 있나"를 낸다.
그리고 게이트는 **기존 점수를 읽어서 판정만** 하므로 `score.py`를 안 건드린다.
지금까지 쌓은 숫자가 무효가 되지 않는다.

일반적인 품질 게이트와 다르게 만든 데가 두 군데 있다.

1. **임계값이 양방향이다.** 보통은 "최소 몇 이상"만 보는데, 우리는 컷 간 유사도에 **상한**이 필요하다.
   4컷이 완전히 똑같으면 1.000으로 만점인데 그건 복붙이라 실패다
2. **천장 대비로 정규화한다.** "정확도 0.95 이상" 같은 절대선은 천장이 1.0일 때 쓰는 것이다.
   우리는 진짜 그림도 0.500이라 절대선이 무의미하다

- **"검색 부품이 생성 부품의 발목을 잡는다"는 아직 가설이다.** 확인하려면 생성물 골든셋이 필요하고,

- 앞 컷 물리기는 **오류가 전파되는 대가**가 있다. 지금은 컷이 독립이라 하나 망해도 나머지는 사는데,
